# 项目章程

- 状态：Accepted
- 日期：2026-07-20
- 项目：标讯截图助手 / Bid Screenshot Assistant

## 1. 一句话定义

输入一个或一批项目名称，系统自动在九个指定标讯平台执行查询，保存搜索结果和公告详情证据，生成可校验归档包并交付给指定收件人，全过程记录任务、平台、步骤、耗时和失败原因。

## 2. 业务目标

- 将人工逐站查询和截图转为可追踪的自动化任务；
- 把“是否查过”升级为“有来源、有时间、有文件哈希的证据”；
- 降低批量项目查询的漏查、错查和重复劳动；
- 在网站改版、登录失效或验证码出现时快速定位并人工接管；
- 为后续每日监控、变更提醒和项目情报建立统一底座。

## 3. 成功定义

首个生产版本应满足：

- 九个平台均有独立 Adapter 与运行状态；
- 100 个真实项目名称测试集中，平台级状态分类准确率达到约定阈值；
- 命中结果可回溯到原始 URL、采集时间和证据文件；
- 单个平台失败不阻断其他平台；
- 用户能重试失败项而不是整批重跑；
- 验证码、扫码和风控不被绕过，能暂停并恢复；
- ZIP、汇总表、manifest 和交付记录一致。

具体量化指标见 PRD。

## 4. 范围

### 4.1 本期范围

- 批量项目名称识别与去重；
- 九个平台查询；
- 结果页/详情页证据采集；
- 任务、平台运行项和证据追踪；
- ZIP 与汇总清单；
- 邮件交付接口；
- JiuwenSwarm Skill、SwarmFlow 与定时任务接入；
- 平台登录态和人工接管。

### 4.2 非本期范围

- 绕过验证码、风控或访问控制；
- 抓取所有全国地方交易平台；
- 自动投标、报名或下载付费标书；
- 对公告作法律真实性背书；
- 以 LLM 猜测页面操作替代平台 Adapter；
- 在未经验证时承诺九平台 100% 可用。

## 5. 工程原则

1. 文档即代码；
2. Adapter-first；
3. 证据链优先；
4. 确定性规则优先，LLM 用于歧义和语义判断；
5. 单平台隔离失败；
6. 可解释状态和人工接管；
7. simulation 与 production 明确分离；
8. 每次平台改版有版本、样例和回归记录。

## 6. 技术定位

JiuwenSwarm 是智能编排和任务渠道层；本仓库是独立业务系统，承担任务数据、Adapter、证据归档、打包、邮件和业务 UI。两者通过 Skill、SwarmFlow 和 MCP/HTTP 工具契约连接，避免直接把业务代码侵入上游框架。

## 7. 治理

- 需求变化：更新 PRD 或新增 ADR；
- 架构变化：必须新增/更新 ADR；
- 平台规则变化：更新平台矩阵、Adapter 版本和回归样例；
- 生产启用：必须通过安全、合规、测试与运维清单；
- 所有过程产物与代码在同一仓库留痕。
