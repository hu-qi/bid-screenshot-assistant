# 产品需求文档（PRD）

- 状态：Baseline / Accepted for implementation
- 版本：0.1
- 日期：2026-07-20

## 1. 背景与问题

标讯人员目前需要逐个打开多个运营商、铁塔、政府采购和公共资源平台，输入项目名称、筛选公告、打开详情、截图、命名、整理并发送。主要问题：

- 平台多、入口不同、登录状态分散；
- 批量项目需要重复操作；
- 无法快速证明某个平台是否实际查询过；
- 未查询到与技术失败容易混淆；
- 截图命名、来源、时间和交付记录不统一；
- 网站改版后通常直到业务人员发现才处理。

## 2. 用户与场景

### 2.1 主要用户

- 标讯查询执行人员；
- 销售/项目人员；
- 管理人员；
- 平台运维和 Adapter 开发人员。

### 2.2 核心场景

1. 临时查询一个项目；
2. 从 Excel 粘贴几十个项目并批量查询；
3. 仅重试失败平台；
4. 定时监控指定项目的新公告；
5. 下载某次查询的完整证据包；
6. 遇到登录/验证码后人工接管并恢复；
7. 平台改版后定位失败步骤并更新 Adapter。

## 3. 用户故事

- 作为查询人员，我输入多个项目名称后，希望自动拆分、去重并预览，避免逐条录入。
- 作为项目负责人，我希望知道每个平台是命中、未命中还是技术失败，而不是只有“失败”。
- 作为审阅者，我希望点击结果即可查看原始 URL、时间和截图，确认查询证据。
- 作为运维人员，我希望看到平台成功率和最近失败步骤，判断是否发生页面改版。
- 作为管理员，我希望配置平台启停、登录态、并发和重试，不修改业务代码。

## 4. 功能需求

### FR-001 新建任务

字段：任务名称、查询名称、邮箱、平台范围、时间范围、公告类型、匹配方式、包含词、排除词、截图范围、执行方式。

验收：至少一个查询名称；默认选择九个平台；任务创建后生成唯一 Task ID。

### FR-002 批量智能识别

支持从文本或 Excel 粘贴内容中按换行、分号、顿号和序号拆分；清理空值和重复项；不擅自改写正式名称。

验收：显示原始条数、清理后条数、重复项和最终预览。

### FR-003 平台执行

按“查询名称 × 平台”生成执行项；平台之间可并行，同一平台内部按 Adapter 流程执行。

验收：单个平台异常不取消其他平台；每个执行项有开始/结束时间和耗时。

### FR-004 搜索与匹配

支持精确、模糊和智能匹配。智能匹配只负责候选排序，必须保留原查询名称和候选标题。

验收：每个命中保存标题、URL、发布日期、公告类型、匹配分和匹配理由。

### FR-005 证据采集

保存结果页和详情页截图或页面快照；生产模式优先 PNG/PDF，模拟模式明确标识 SVG/HTML 占位证据。

验收：证据记录 URL、采集时间、类型、文件大小和 SHA-256。

### FR-006 状态分类

执行项状态至少包含：`PENDING`、`RUNNING`、`FOUND`、`NOT_FOUND`、`PARTIAL`、`LOGIN_REQUIRED`、`CAPTCHA_REQUIRED`、`PAGE_CHANGED`、`TIMEOUT`、`PLATFORM_ERROR`、`FAILED`。

验收：`NOT_FOUND` 必须有成功完成搜索的页面证据；无法完成搜索不能标记为 `NOT_FOUND`。

### FR-007 重试与恢复

支持重试单个执行项、全部失败项和完整任务；沿用浏览器会话恢复人工验证后的流程。

验收：重试生成新 attempt，保留旧 attempt，不覆盖历史。

### FR-008 结果查看

任务列表显示进度、命中、失败、耗时和邮件状态；详情使用查询名称 × 平台矩阵。

验收：点击单元格可查看执行步骤、反馈、命中和证据。

### FR-009 打包下载

生成目录化 ZIP，包含汇总 JSON/CSV（后续 XLSX）、manifest、运行报告和每个平台证据。

验收：manifest 中的哈希可重新计算验证；文件数量与数据库记录一致。

### FR-010 邮件与渠道交付

支持发送任务摘要与 ZIP/下载链接；邮件失败不改变采集结果状态。

验收：独立记录 delivery status、收件人、时间、附件或链接、错误信息。

### FR-011 定时监控

通过 JiuwenSwarm Cron 或业务调度器周期执行；只推送新增或变化公告。

验收：同一公告不会在无变化时重复推送；可查看每次定时运行。

### FR-012 平台管理

显示 Adapter 版本、状态、登录态、最近成功率、连续失败和最后回归时间。

验收：平台可单独停用；停用平台不会生成技术失败。

## 5. 非功能需求

### NFR-001 可追溯

所有任务、运行、执行项和证据具有稳定 ID，并贯穿日志与归档。

### NFR-002 可靠性

平台级失败隔离；幂等创建；重复发送保护；进程异常后可恢复状态。

### NFR-003 性能

默认最大并发 4 个平台，可配置；100 个名称不能一次无界展开，必须有批次和队列。

### NFR-004 安全

凭据不进入代码和日志；Cookies/Profiles 按环境隔离；验证码由人工处理；敏感下载链接有期限。

### NFR-005 可维护性

每个平台独立 Adapter、样例与测试；选择器和平台规则有版本；公共协议保持稳定。

### NFR-006 可观测性

指标至少包括：平台成功率、状态分布、平均/P95 耗时、连续失败、人工接管次数、交付失败。

## 6. 归档结构

```text
标讯截图_<任务名称>_<运行时间>.zip
├── summary.json
├── manifest.json
├── report.html
└── queries/<query-slug>/<platform-id>/
    ├── result-page.png|svg
    ├── detail-001.png|svg
    └── metadata.json
```

## 7. 关键指标

首个生产试点建议目标：

- 平台执行项状态分类准确率 ≥ 98%；
- 证据文件与 manifest 一致率 100%；
- 非验证码场景可自动完成率 ≥ 90%（按已启用平台样例集）；
- 单平台失败隔离率 100%；
- 失败原因可定位到具体步骤比例 ≥ 95%；
- 同一失败项可独立重试率 100%。

这些指标需要用真实测试集校准，不作为当前模拟骨架的完成声明。

## 8. MVP 验收

MVP 先选择 3 个差异明显的平台，完成真实搜索、证据、归档和重试闭环。九个平台都保留 Adapter 协议和状态，但未验证平台保持 `experimental/disabled`。
